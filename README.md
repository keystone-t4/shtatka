# Штатка — PWA

Состав:
- `index.html` — стартовая страница; при первом входе баннер cookie.
- `register.html` — регистрация (`register.css`, `register.js`, исходники в `register-src/`): ИНН → о себе и согласия → код из СМС → «Кабинет создан» и выбор способа подтверждения компании. Тот же экран открывается по `register.html#verify`.
- `cabinet.html` — главная личного кабинета (`cabinet.css`, `cabinet-widgets.js`, `home-store.js`, `cabinet.js`).
- `people.html`, `company.html`, `tariff.html` — разделы «Люди», «Компания», «Тариф и оплата». Меню слева общее для всех страниц: `shell.js`.
- `customize.html` — страница «Настроить главную»: галерея 13 макетов, конструктор, структура компании, оформление (`customize.css`, `customize.js`, картинки в `tplshots/`).
- `policy.html`, `consent.html`, `offer.html`, `ads.html`, `cookie.html` — юридические документы (редакция от 28.10.2026).
- `offline.html`, `manifest.webmanifest`, `sw.js`, `icons/` — установка как приложение и офлайн.
- `config.js` — настройки.

## Запуск локально
```
cd shtatka-pwa
python3 -m http.server 8080
```
Откройте http://localhost:8080. Установка как приложение и офлайн работают только по http://localhost или HTTPS.

## Мои данные и пример
- Если человек зарегистрировался в этом браузере, кабинет показывает **его данные**: сначала пусто, блок «Первые шаги» (подтвердить компанию, добавить сотрудников, анкета компании, главная, тариф) и при первом входе окно из трёх слайдов «Первые шаги».
- Без регистрации и по кнопке «Посмотреть на примере» кабинет показывает пример с вымышленными данными. Просмотр шаблона `cabinet.html?tpl=...` — тоже пример.
- «Люди»: принять нового, загрузить договоры действующих (фото/скан), бесплатная проверка шаблона договора. Вносить сотрудников можно после подтверждения компании; в демо-режиме (пустой `apiUrl`) есть кнопка «Продолжить в демо».
- Распознавание договоров, проверка шаблона, счёт и ссылка на анкету сотрудника работают только с сервером: сейчас интерфейс честно пишет, что подключим позже.

## Главная кабинета: как устроено
**Меню и блоки не дублируют друг друга.** Меню слева — разделы, где работают (Заявки и задания, Люди, Время, Документы и сроки, Знания и объявления, Расходы на людей). Блоки на главной — сигналы: исключения и то, что требует решения, с переходом в раздел. Блок не должен повторять список из раздела.

**Страница `customize.html`** (кнопка «Настроить главную»), четыре вкладки:
1. Варианты: 13 готовых по отраслям (просмотр, «Взять за основу», «★ Начальным»), свои варианты.
2. Конструктор: список блоков слева (перетаскивание или «+»), справа живой макет с порядком 1, 2, 3…, размеры S/M/L, ◀ ▶, удалить. «Сохранить вариант» и «★ Сделать начальным экраном».
3. Структура компании: точки, проекты, города, офисы, отделы (название, тип, число людей) или пример для отрасли. После этого сверху на главной работает переключатель «Вся компания ▾», а в конструкторе доступен блок «По подразделениям».
4. Оформление: тема и цвет компании.

**Где что лежит**
- `cabinet-widgets.js`: блок описывается строкой `def(id, группа, название, размеры, размер по умолчанию, тон, c => html)`; шаблоны по отраслям — массив `TPL`; демо-данные — объект `DEMO`.
- `home-store.js`: всё, что сохраняется (ключ `shtatka-home-v2`): свои варианты, начальный экран (`tpl:<id>` или `my:<id>`), структура компании, выбранный срез, оформление. Когда появится сервер, заменить нужно только `load()` и `persist()`.
- Черновик конструктора хранится отдельно (`shtatka-home-draft`), поэтому незавершённая правка не теряется при выходе.
- Посмотреть любой шаблон без сохранения: `cabinet.html?tpl=cafe` (base, cafe, retail, factory, warehouse, transport, auto, build, clean, beauty, clinic, hotel, office).
- Срез (подразделение) пока меняет заголовок, блок «В штате» и блок «По подразделениям». Остальные цифры демо и пересчитаются по срезу, когда подключим данные.

## config.js
| Поле | Что это | Если пусто |
|---|---|---|
| `apiUrl` | адрес бэкенда, например `https://api.штатка.рф` | заявки сохраняются в браузере |
| `companyUrl` | адрес сервиса сведений о компаниях, например `https://api.штатка.рф/company` | `{apiUrl}/company`; без `apiUrl` — DaData или демо |
| `dadataToken` | ключ DaData для поиска компании по ИНН | демо-карточка компании |
| `metrikaId` | номер счётчика Яндекс Метрики | аналитика не загружается |
| `docsVersion` | редакция документов, пишется вместе с согласиями | — |
| `supportEmail` | почта поддержки для ссылок «Напишите нам» | ссылка показывает подсказку |

Метрика загружается только после «Принять» в баннере cookie.

## Данные компании по ИНН
Порядок источников (`company-data.js`):
1. Свой сервис `server/company-proxy.mjs` — основной. Браузер не может обращаться к сайтам ФНС напрямую (CORS), поэтому запрос идёт через сервер.
   - ЕГРЮЛ/ЕГРИП (egrul.nalog.ru): название, ОГРН, КПП, адрес, руководитель, даты регистрации и прекращения.
   - Реестр МСП (rmsp.nalog.ru): категория — микро, малое, среднее.
   - DaData, если задан `DADATA_TOKEN`: основной ОКВЭД, налоговый режим (только на платных тарифах DaData), процесс ликвидации. Запасной источник реквизитов.
2. DaData из браузера, если в `config.js` указан `dadataToken`.
3. Без источников — демо-карточка.

Запуск сервиса: `DADATA_TOKEN=… ALLOW_ORIGIN=https://штатка.рф node server/company-proxy.mjs` (Node 18+, без зависимостей, порт 8787). Готовые настройки для сервера — в `server/deploy/`: юнит systemd, nginx с HTTPS и лимитом запросов, образец `company.env`, проверка `check.sh`. Пошаговая инструкция — документ «Штатка — подключение к сайтам ФНС». Ответ: `GET /company?inn=…` → 200 (JSON), 400 `bad_inn`, 404 `not_found`, 502 `upstream`.
Кэш — сутки, к ФНС не чаще раза в секунду. У сайтов ФНС нет официального API: формат может поменяться, может появиться капча. На этот случай подключён DaData. Обращения к сайтам ФНС проверены только на тестовых ответах, поэтому после выкладки сервиса нужно проверить их на боевом сервере.

Компания со статусом «ликвидирована» или «прекратила деятельность» к регистрации не допускается. ОКВЭД, статус МСП и налоговый режим сохраняются в сессии и подставляются в раздел «Зарплата» (блок «Компания и тариф взносов»).

## Зарплата: взносы и платежи (2026)
Правила — `payroll-rules.js`, расчёт по сотрудникам — `payroll()` в `hr-core.js`, страница — `hr.js` → `payroll`. Взносы в три слоя:
1. Ядро: 30 % до предельной базы 2 979 000 ₽ нарастающим итогом, 15,1 % сверх. База — начислено без пособия по больничному; за руководителя не меньше МРОТ (флаг в карточке или должность «Директор»/«Генеральный директор»).
2. Льгота компании: МСП из перечня 4125-р при доле дохода ≥ 70 % — 15 % с части выше 1,5 МРОТ (обработка — 7,6 %); IT — 15 % / 7,6 %; АУСН — 0, травматизм 2 959 ₽ в год. Настройки и загрузка по ИНН — на странице «Зарплата», ключ `shtatka-payroll-co`.
3. Надбавки сотрудника (карточка → «Данные»): доп. тариф ОПС по СОУТ 2/4/6/7/8 % или по спискам досрочной пенсии 9 % / 6 % (ст. 428 НК), без предельной базы.
Травматизм — ставка СФР × (1 − скидка до 40 %). На странице: раскладка по слоям, формулы, сроки уплаты, выгрузка CSV.
Не учтено: взносы по ГПХ, особые ставки для иностранцев (ВКС, патент), ОЭЗ/НКО, разбивка 30 % на ОПС/ОМС/ВНиМ — проверить у бухгалтера.

## Регистрация и подтверждение компании
Зарегистрироваться может любой сотрудник компании. Регистрация открывает **ознакомительный режим**: пример кабинета, анкета компании, настройка главной. Вносить данные сотрудников, приглашать их и готовить документы можно только после **подтверждения компании** (оферта, раздел 3):
1. Электронная подпись: заявление о присоединении к оферте подписывает руководитель или ИП своей КЭП из налоговой либо сотрудник КЭП физлица с машиночитаемой доверенностью. Сервер сверяет ИНН и ОГРН из сертификата (и доверенности) с ЕГРЮЛ/ЕГРИП и с ИНН из регистрации, ФИО руководителя — с ЕГРЮЛ; МЧД — по реестру ФНС.
2. Оплата первого счёта с расчётного счёта: ИНН плательщика в платёжном поручении должен совпасть с ИНН из регистрации.
3. Позже: СберБизнес ID или Т-Бизнес ID (нужен договор с банком).

Правила для сервера:
- Один ИНН — один кабинет. Повторная регистрация того же ИНН — ответ **409**, страница покажет «компания уже есть в Штатке».
- Пока компания не подтверждена, сервер не принимает данные сотрудников (не только интерфейс).
- Если компания сообщила, что не поручала регистрацию, кабинет закрывается, данные удаляются в течение 3 рабочих дней (оферта, п. 3.6).
- Неподтверждённые кабинеты стоит автоматически удалять через разумный срок (например, 30 дней) с предупреждением на почту.

## Публикация
Нужен HTTPS. Подойдёт любой статический хостинг в РФ (Yandex Object Storage, Selectel, Timeweb, nginx). Данные клиентов должны храниться на серверах в РФ.

## Кадровое ядро (ноябрь 2026)
- `hr-core.js`: единая запись сотрудника и все правила. Приём (`hire`) и увольнение (`fire`) создают сроки, воинский учёт, иностранцев, события ЕФС-1, архив. Хранение: `shtatka-hr-v1` (свои данные), `shtatka-hr-demo` (пример).
- `people.js`: приём, увольнение, карточка (данные, документы, воинский учёт, иностранец, трудовая и стаж, больничные, история), загрузка списком.
- `hr.html` + `hr.js`: разделы docs, military, foreign, sick, payroll, archive, laws (одна заготовка, страницы создаёт build_pwa.py).
- Все нормы и сроки помечены «проверить»: до запуска их сверяет юрист. Праздники в расчёте рабочих дней не учтены.

## Приём сотрудника, паспорт, договор, структура (ноябрь 2026)
- «Люди» → «+ Принять»: два шага. **1. Человек**: паспорт по фото (главный разворот и прописка; на телефоне — «Сфотографировать» или «Из галереи или файла», на компьютере — файл JPG, PNG, PDF) или вручную: ФИО по отдельности, пол, дата и место рождения, серия и номер, дата выдачи, кем выдан, код подразделения, адрес и дата регистрации, телефон, СНИЛС, ИНН, воинский учёт, документы иностранца. Поля, заполненные по фото, подсвечены. **2. Договор**: должность, вид (трудовой бессрочный или срочный с датой и основанием, ГПХ, самозанятый, аренда у физлица), оплата, ставка, дата начала, испытательный срок, режим, подразделение, руководитель, место работы, дистанционно, патент (уведомление ИФНС и аванс), травматизм по ГПХ. После сохранения сразу открывается черновик договора.
- В карточке: «Создать договор» (тот же шаг 2 для действующего), блок «Паспорт и адрес», руководитель и подчинённые. «Структура» в «Людях» — дерево подчинённости; циклы запрещены.
- Проверки: ИНН и СНИЛС, паспорт РФ к замене в 20 и 45 лет, испытательный срок младше 18 лет и по срочному до 2 месяцев, оклад ниже МРОТ с учётом ставки.
- Распознавание: `passport.js` уменьшает фото в браузере (до 2400 px, JPEG) и шлёт на `POST {passportUrl}` → `server/company-proxy.mjs` → Yandex Vision OCR (модель `passport` — главный разворот, `page` — прописка, адрес выделяется из текста). Нужны `YC_API_KEY` и `YC_FOLDER_ID`; логирование у Яндекса выключено, фото не сохраняется. Без сервера — демо-пример с пометкой. Иностранные паспорта модель не читает: ввод вручную. Альтернативы для своего контура: Smart Engines, Dbrain (цена по запросу).
- Шаблоны договоров: `contract-template.js` (трудовой, ГПХ, аренда, самозанятый). Свою форму вставьте вместо текста, метки `{{…}}` перечислены в начале файла. Номер договора закрепляется при создании.

## Самозанятые и выгрузка для 1С (ноябрь 2026)
- Статус самозанятого: кнопка «Проверить в ФНС» в договоре с самозанятым и в карточке. Запрос идёт через `GET /npd?inn=` (server/company-proxy.mjs → statusnpd.nalog.ru): ФНС пускает 2 запроса в минуту с IP, поэтому очередь раз в 31 с и запоминание на сутки. Если ФНС не видит статуса, договор с самозанятым не создаётся. В списке «Людей»: «самозанятый ✓» (проверено за 30 дней) или «проверить НПД». Без сервера — подсказка проверить вручную на npd.nalog.ru/check-status, статус не выдумывается.
- Руководитель у ГПХ или самозанятого — предупреждение о признаках трудовых отношений.
- «Люди» → «Выгрузить для 1С»: CSV (UTF-8, «;», даты ДД.ММ.ГГГГ) — ФИО по отдельности, пол, рождение, гражданство, ИНН, СНИЛС, паспорт, адрес, должность, подразделение, договор, даты, ставка, оклад, испытательный срок, руководитель, документ иностранца. Готового формата загрузки в ЗУП нет: файл берут обработки загрузки физлиц и сотрудников из Excel.

## Личное дело и документы сотрудника (v10)
- Карточка → «Личное дело» (`dossier.js`): перечень под конкретного человека — обязательные по ст. 65 ТК (паспорт, трудовая или СТД, СНИЛС, военный билет, согласие на ПД), по должности (диплом, медкнижка, права, справки о судимости и наркотиках), для иностранцев по ст. 327.3 ТК (национальный паспорт с переводом, патент и чеки, разрешение, РВП/ВНЖ, ДМС для ВКС, миграционная карта, уведомление о прибытии, проверка реестра контролируемых лиц), по желанию (ИНН, справка 182н, документы на вычет, реквизиты карты, смена фамилии). У каждого — «Зачем», статья, отметка «оригинал предъявлен» или копия (фото, галерея, PDF), срок действия с напоминанием за 30 дней.
- Копии — IndexedDB `shtatka-files` в браузере до подключения сервера. Требовать документы сверх закона нельзя (ч. 3 ст. 65 ТК) — это написано в карточке.
- Приём: плитка «СНИЛС» (распознавание `POST /passport` с `kind: snils`, проверка контрольного числа), галочка «Сохранить копии в личное дело». Иностранцы — вручную, плитки скрыты.
- Документы: договор о полной материальной ответственности (`mat` в contract-template.js) для кассиров, продавцов, кладовщиков, операторов ПВЗ от 18 лет.
- «Люди» → «Список для заказчика»: CSV без паспортов и адресов — объект, должность, гражданство, сроки документа на работу, медкнижки, прав, удостоверения.
- Итоги прогона панели ролей — в проекте: «Штатка — прогон панели ролей 03.11.2026».

## Подбор документов, анкета сотрудника, вход по ЭЦП (v11)

**Подбор документов (jobs.js).** Что просить у сотрудника, зависит от отрасли (выбор вручную, иначе по ОКВЭД), должности, удалёнки и возраста. Медкнижка нужна пекарю, продавцу продуктов, парикмахеру, воспитателю; не нужна бухгалтеру на удалёнке; бухгалтера в пекарне Штатка спрашивает, контактирует ли он с продуктом. Подсказки видны в форме приёма и в «Личном деле». Список не заменяет ст. 65 ТК: лишнего требовать нельзя.

**Анкета сотрудника (anketa.html).** Ссылка-приглашение содержит JSON в `#i=` (или `?t=` с запросом `GET {apiUrl}/anketa/{token}`). Сотрудник заполняет данные, прикладывает копии, ставит согласие на обработку. Ответ уходит `POST {apiUrl}/anketa/{id}`; без сервера работает режим «файл»: сотрудник присылает файл, вы загружаете его в «Входящие» на странице «Люди».

**Вход по ЭЦП (esign.js + server/esign.mjs).** Сервер выдаёт строку-вызов (одноразовая, 5 минут, с адресом сайта). Плагин КриптоПро подписывает её на токене. Сервер проверяет подпись, срок, цепочку до аккредитованных УЦ, отзыв по списку отзыва и сверяет ИНН, ОГРН и руководителя с ЕГРЮЛ. Компания считается подтверждённой, только если подписал руководитель. Сотрудник подтверждает личность и прикладывает МЧД; МЧД пока проверяется вручную по реестру ФНС.
Нужно на сервере: список УЦ (`ESIGN_CA_BUNDLE`, из TSL e-trust.gosuslugi.ru), OpenSSL с gost-engine для ГОСТ-подписей, `ESIGN_SECRET`, в nginx блок `/auth/` (см. nginx-api.conf). В config.js необязательно: `authUrl`, `cadespluginUrl`.
Ограничения: нужен компьютер с КриптоПро CSP, плагином и расширением; с телефона подпись токеном недоступна, остаётся оплата счёта. Проверено на тестовых сертификатах (RSA) и имитации плагина; боевую ГОСТ-подпись и реальный токен нужно проверить на вашем сервере до запуска.

## График смен (v12)

Раздел «График смен» (time.html, schedule.js, time.js). Хранится в данных кадрового ядра (`sch`): виды смен, ячейки «сотрудник|дата», список включённых вручную.
- Показ: пункт меню включается сам, если сфера со сменами (`needsShifts` в jobs.js). Офисным компаниям раздел сообщает, что график не нужен, и даёт кнопку «Включить».
- В графике: сотрудники со сменным режимом или 2/2 и сотрудники сменных сфер, кроме офисных ролей и удалёнки. Включить или выключить человека можно во вкладке «График» его карточки.
- Телефон: день за днём, смена назначается одним нажатием. Компьютер: неделя × люди, нажатие по ячейке перебирает смены.
- Проверки: нет выходного за неделю (ст. 110 ТК), меньше 11 часов между сменами, ночная смена несовершеннолетнему (ст. 96), смена при больничном, работа в праздник (ст. 153). Праздники — только с фиксированной датой (ст. 112); переносы по производственному календарю не учитываются.
- Для бухгалтера: часы за месяц, ночные (22:00–06:00), часы в праздники, выгрузка для Excel.
- Виджет «Смены сегодня» на главной считает людей по сменам при реальных данных.

## Личный кабинет сотрудника (v13)

Страницы me.html, me.js, me.css, me-core.js. Два типа пользователей: на register.html переключатель «Я работодатель / Я сотрудник».
- Доступ. Работодатель в карточке сотрудника, вкладка «Кабинет», нажимает «Создать доступ». Появляются ссылка и 8-значный код. Данные сотрудника (договоры, согласие, график на 28 дней, остаток отпуска, срок патента) шифруются кодом (PBKDF2 250 000 итераций, AES-GCM) и лежат в самой ссылке. Ссылку и код отправляют разными каналами. Паспортных данных, оклада и служебных заметок в ссылке нет. Ссылка действует 14 дней на первое открытие; после ввода кода данные остаются на устройстве сотрудника.
- Что видит сотрудник: «Главная» (смена сегодня, ближайшие смены, остаток отпуска, срок патента для иностранцев), «Документы» (договор, согласие, приказ), «Отпуск» (заявление).
- Заявление на отпуск уходит работодателю ссылкой people.html#v=… (через «Поделиться» или буфер обмена). Работодатель открывает её, видит даты и остаток и нажимает «Согласовать»: дни списываются, запись попадает в историю. Если в config.js задан apiUrl, заявление дополнительно отправляется POST {apiUrl}/me/request.
- Ограничение: без сервера данные в кабинете сотрудника не обновляются сами и доступ нельзя отозвать. При смене графика или отпуска работодатель создаёт доступ заново. Сервер должен заменить ссылку на токен, а данные отдавать по запросу: GET {apiUrl}/me, POST {apiUrl}/me/request, DELETE для отзыва.

## Обновление паспортных данных сотрудником (v14)

В кабинете сотрудника вкладка «Данные»: «Новый паспорт» (смена фамилии, замена по возрасту, утеря) и «Новая прописка». Сотрудник прикладывает фото, passport.js присылает его на `/passport`, поля подставляются, сотрудник проверяет и отправляет. Работодатель открывает ссылку people.html#v=… и видит таблицу «было — станет», жмёт «Применить». У иностранных граждан данные вносит работодатель. Фото в ссылке не передаются: без сервера их присылают в мессенджере; с `apiUrl` фото уходят в `POST {apiUrl}/me/request` (поле `files`, base64). Паспортные номера в браузере сотрудника не сохраняются.

## Приглашение сотрудника в кабинет (v15)

СМС не используются. В разделе «Люди» у каждого сотрудника кнопка «Пригласить». В окне ФИО (не меняется) и почта из карточки (можно исправить, сохраняется в карточке). Кнопка «Отправить приглашение» создаёт ссылку и код. Без сервера письмо открывается в почте работодателя (на телефоне через «Поделиться»); если ссылка слишком длинная для mailto, текст копируется в буфер, его нужно вставить в письмо. Код показывается работодателю в окне и в письмо не входит. С `apiUrl` отправку берёт на себя сервер: `POST {apiUrl}/me/invite` с `{empId,email,fio,company,link}`. Поле почты есть в форме приёма, в карточке и в анкете сотрудника.

## Статусы приглашения (v16)

В списке «Люди»: «Пригласить» → «приглашён до дд.мм» → «в Штатке»; если срок вышел, «приглашение истекло: повторить». Ссылка-приглашение действует 7 суток (168 часов) на первый вход, время хранится в `expAt`. После ввода кода у сотрудника на главной кнопка «Сообщить работодателю»: отправляет ссылку people.html#v=… (тип `joined`), и у работодателя статус меняется на «в Штатке». С `apiUrl` статус ставит сервер автоматически: кабинет сам вызывает `POST {apiUrl}/me/joined` с `{inviteId, empId}`.

## Документы компании (v17)

Раздел «Компания» → «Документы компании» (company-docs.js, cdocs.css). Перечень локальных документов, которые регулируют работу сотрудников: учредительные и полномочия (устав, выписка, решение о директоре, доверенность), трудовые (правила внутреннего распорядка, штатное расписание, график отпусков, положение об оплате труда и др.), персональные данные, охрана труда и воинский учёт, документы по сфере (общепит: производственный контроль, ХАССП, журнал допуска по медкнижкам; IT: коммерческая тайна, NDA, политика ИБ). Набор зависит от формы (у ИП нет устава), сферы, числа сотрудников и удалёнки. Статусы: загружен, нет (надо создать), не нужен. Файлы лежат в IndexedDB браузера. Кнопка «Создать с нуля» пока неактивна: шаблоны добавим следующим шагом.

## Чтение устава и создание документов (v18)

Загруженный в «Документы компании» PDF устава читает ustav-reader.js (pdf.js от Mozilla лежит в vendor/pdfjs/, лицензия Apache-2.0): наименование, место нахождения, уставный капитал, руководитель и срок, «действует без доверенности», порядок крупных сделок. Результат сверяется с анкетой компании и названием из регистрации, расхождения показываются предупреждением. Работает с PDF, где есть текст; скан без распознавания не читается (пока объясняем это). Кнопка «Создать с нуля» работает для: правил внутреннего трудового распорядка, приказов об ответственных за персональные данные, охрану труда и воинский учёт, графика отпусков. Приказ об отпуске показывается из окна заявления в «Люди». Все документы — образцы, их нужно проверить.
